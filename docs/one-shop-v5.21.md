# 원샵 v5.21.0 — 손님 재요청과 최종 합의

프로덕션북의 통합 시연에 대안 수정·재요청을 추가했다. 메뉴판 등록 → QR·언어 선택 → 주문·예약 → 변경 요청 → 직원 대안 → 손님 재요청 → 직원 최종 합의 → 접수·조리·알림을 한 페이지에서 체험한다.

## 시연 방법

1. 매장 주문·예약·온라인 배달 중 선택하고 주문/예약 확인까지 진행한다.
2. 손님 화면에서 변경 요청을 보낸다. 홀 또는 사장님이 사유를 고르고 다른 메뉴·수량 또는 예약 시간을 제안한다.
3. 손님이 자기 언어의 **내용 바꿔 다시 요청**을 선택한다. 직원의 제안값이 미리 들어 있다. 메뉴별 수량 또는 예약 날짜·시간을 바꾸고 재요청한다.
4. 홀이나 사장님이 현재 확정 내용, 직원이 보낸 대안, 손님 재요청을 비교한다. **재요청 확인 · 최종 합의**를 누르면 네 화면이 함께 갱신된다.
5. 합의하지 못하면 사유와 새 대안을 보낸다. 손님은 새 대안을 수락하거나 다시 수정할 수 있다. 각 왕복이 별도 기록으로 남는다.
6. 합의 후 다음 단계로 진행하면 홀 접수, 주방 조리·준비 완료, 손님 알림까지 이어진다.

## 동작과 권한

- 재요청 중에는 확정 주문/예약을 변경하지 않는다. 다음 처리 단계는 대기한다.
- 조리 시작 전에는 홀 또는 사장님, 시작 후에는 사장님만 재요청을 승인할 수 있다. 조리 중 메뉴가 바뀌면 주방 준비 단계부터 다시 진행한다.
- 편집 취소는 원래 대안으로 돌아간다. 동일한 내용은 재요청 대신 수락하도록 안내한다. 잘못된 수량·예약 시간은 입력을 유지한 채 수정 안내를 표시한다.
- 재요청에서는 메뉴·수량 또는 날짜·시간만 수정한다. 예약 인원과 확정된 배달 주소·연락처는 유지한다. 최초 변경 요청에서는 기존처럼 이 정보도 변경할 수 있다.
- 주방은 메뉴·수량과 처리 결과만 본다. 주소·연락처·가격·원문·개인별 처리 기록은 전달하지 않는다. 예약은 처리 상태만 표시하고 조리 작업을 만들지 않는다.
- 최종 승인 시점에 예약 시간을 다시 검증한다. 지난 시간은 승인할 수 없고 새 시간을 제안해야 한다.
- 요청·제안 ID, 시연 실행 ID, 상태 버전, 역할을 확인해 이전 버튼/중복 응답이 새 내용을 덮어쓰지 않게 했다.

## 처리 기록

기존 요청과 직원 대안을 덮어쓰지 않고 새 재요청을 연결한다. 왕복 차수, 원 요청/제안 ID, 한국어와 손님 언어의 요청·제안·응답·최종 내용, 가상 손님/직원 이름 및 UTC+7 시각을 남긴다. 사장님 처리 기록에서 상세 내용을 펼쳐볼 수 있다.

기록은 현재 통합 시연 화면의 메모리에만 있다. 새로고침·처음부터·시나리오 변경 시 초기화된다. 실제 샵 데이터, 실제 AI, 결제, 메일, 외부 알림에는 연결하지 않았다. 기존 별도 샵 앱의 클라우드 기능은 변경하지 않았다.
