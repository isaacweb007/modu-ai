# 5.11.0 — 사장님 비밀번호와 관리 세션

사장님앱은 샵별 비밀번호를 검증한 뒤에만 관리 데이터를 불러온다. 손님·직원 토큰은 사장님 조회·설정 API에 사용할 수 없다. 프로덕션북의 공개 네 화면 시연은 계속 준비된 가상 데이터로 작동한다. 실제 AI·결제는 연결하지 않았다.

## 이용 흐름

1. 기존 샵은 기존 관리 키가 저장된 기기에서 최초 비밀번호를 설정한다. 다른 기기나 손님 링크로는 최초 설정 권한이 없다.
2. 새 샵은 비밀번호를 설정하면 본인 전용 주모 데모 샵이 생성된다. 메뉴, 미결제 샘플 주문 1건, 다음 날 예약 1건을 함께 저장한다.
3. 로그인 후 `로그인 · 보안`에서 관리 링크를 복사한다. 다른 기기에서는 이 링크와 같은 비밀번호로 같은 샵에 접속한다. 관리 링크 자체에는 인증 토큰이 없다.
4. 비밀번호를 변경하려면 현재 비밀번호를 확인한다. 변경 트랜잭션에서 모든 기존 사장님 세션을 폐기하고 변경한 기기에 새 세션을 발급한다. 직원 전용 링크에는 영향을 주지 않는다.
5. 로그아웃은 서버 세션을 폐기한 다음 해당 브라우저의 관리 캐시를 지운다. 주문·예약·샵 데이터는 서버에 유지된다. 세션은 12시간 후 만료된다.

## 접근 제어

- 비밀번호는 12–128자, UTF-8 최대 512바이트. WebCrypto PBKDF2-SHA256 600,000회와 매번 생성하는 16바이트 소금값을 사용한다. 비밀번호 원문은 저장·응답·로그에 남기지 않는다.
- 사장님 세션은 무작위 256비트 토큰이며 DB에는 SHA-256 해시만 저장한다. 매 요청마다 샵 ID·만료·폐기를 검증한다.
- 비밀번호 검증 요청은 IP·샵별로 제한한다. 검증과 동시에 비밀번호가 변경될 경우 revision 잠금으로 이전 비밀번호의 세션 발급을 거부한다.
- 비밀번호·세션 테이블은 RLS와 직접 접근 거부 정책을 사용한다. 관련 RPC는 service_role만 실행할 수 있는 security invoker 함수다.
- 기존 관리 키는 비밀번호 최초 설정만 가능하다. 기존 키로 주문 조회, 직원 등록, 매장 수정 등을 수행할 수 없다.
- 직원은 전용 링크와 서버 역할별 projection을 사용한다. 주방에는 가격·배달 연락처·사장님 설정을 보내지 않는다. 홀의 접수 및 주방의 준비 완료 상태 변경은 기존 서버 권한 규칙을 유지한다.
- 직원 삭제·권한 변경·링크 교체는 다음 요청과 실시간 재조회에 반영된다. Broadcast에는 비공개 주문이나 인증 정보를 넣지 않고 재조회 신호만 보낸다.
- 탭 사이 로그인 변경, 비밀번호 변경, 로그아웃과 오래된 비동기 응답이 충돌해도 새 세션을 덮어쓰거나 폐기하지 않도록 저장 토큰과 작업 세대를 함께 확인한다.

## 화면과 번역

한국어 기본, 기존 9개 언어에 로그인·최초 설정·보안 설정·오류·프로덕션북 설명을 추가했다. 비밀번호 표시 전환, 자동 완성, 붙여넣기, 명시적 레이블, 모바일 터치 영역을 제공한다. 390px 화면에서 가로 넘침 없이 설정·로그아웃·로그인 폼을 사용할 수 있다.

## 검증

- 로컬 단위·상태·권한·번역·비동기 경합 테스트와 JavaScript 번들 검사를 수행했다.
- `scripts/verify-owner-auth.mjs`: 실제 서버 API 42개 검증. 최초 설정·잘못된 비밀번호·교차 샵 거부·다른 기기 로그인·로그아웃 재사용 거부·비밀번호 변경 후 기존 세션 해제·직원/손님 사장님 API 거부·직접 DB/RPC 거부·새 데모 생성.
- `scripts/verify-staff-cloud.mjs`: 실제 서버 API 48개 검증. 홀·주방·사장님·손님 상태 동기화, 직원 권한 변경·삭제·링크 교체, 제한된 데이터 응답, 비공개 데이터 없는 실시간 신호.
- Supabase 보안 advisor: 이 변경 후 lint 없음.
- 격리된 개발 검증 샵만 사용했다. 테스트 비밀번호·토큰은 git에서 제외된 `artifacts/`의 0600 파일에 보관한다.

## 남은 범위

직원 전용 링크는 소지자 기반 접근이다. 직원 본인 확인, 이메일/Google 로그인, 자동 이메일 비밀번호 복구, MFA는 아직 제공하지 않는다. 사장님 비밀번호를 모르면 자동으로 초기화할 수 없으며 별도 소유권 확인이 필요하다. HTTP 전용 쿠키를 사용하는 동일 출처 인증 서버로 바꾸기 전까지 브라우저 세션은 localStorage에 저장한다. 실제 사용자 인증·복구 체계는 상용 서비스 전 별도 구축 대상이다.

## 배포

마이그레이션 `20261028015613_owner_password_sessions.sql`을 적용하고 `modu-api` Edge Function v10을 배포했다. 프런트엔드 5.11.0은 동일 커밋으로 GitHub Pages와 기존 소유자 전용 Sites에 배포한다. 공개 주소와 사이트 접근 범위는 유지한다.
