# 원샵 5.6 · 라미 통역 데모

손님 언어의 요청을 사장님에게 한국어와 원문으로 나란히 보여주고, 사장님이 미리 준비된 한국어 답변을 선택해 보내면 해당 손님에게 원래 요청 언어로 전달한다. 실제 모델·번역 API·결제는 호출하지 않는다.

## 체험

- 프로덕션북의 체험 섹션 → 라미 통역 → 손님 화면 / 사장님 통역함.
- 사장님앱 로그인 버튼 → 샵 현황의 라미 통역함. 베트남어 샘플 요청 1개가 준비된다. 기존 샘플 데이터는 초기화하지 않는다.
- 같은 브라우저에서 두 화면을 열어 즉시 체험할 수 있다. 다른 휴대폰과 연결하려면 기존 '실시간 데모 샵 열기' 후 그 샵의 QR/링크를 사용한다.
- 손님은 상황 버튼을 누르거나 준비된 요청 문장을 입력한다. 사장님은 원문과 한국어 뜻, 테이블/온라인 출처를 확인하고 답변을 펼쳐 전송한다.
- 한국어·영어·베트남어·중국어·일본어·크메르어·인도네시아어·라오어·힌디어. 물과 앞접시, 덜 맵게, 땅콩 알레르기, 음식 지연, 김치전 1개 주문, 2명 예약의 6개 상황.
- 일반 자유문장 번역 기능이 아니다. 통역 모드에서 준비되지 않은 문장은 상황 선택 안내를 표시한다. 의역/부정/수량 변경을 임의로 추론하지 않는다. 현지 원어민 감수는 미실시.
- 주문·예약 문의는 실제 주문/예약을 자동 생성하지 않는다. 메뉴·수량·이용 정보 또는 예약 날짜·시간을 별도 확인해 제출한다.

## 저장과 전달

기존 `modu_messages`의 thread payload에 원문·한국어·시나리오·언어·답변 연결 ID를 저장한다. 스키마 변경 없이 기존 Realtime 무민감정보 갱신 신호 및 snapshot 접근 제어를 재사용한다.

- `POST /:store/interpreter`: 인증된 손님만. 준비된 언어/문장/시나리오를 서버에서 확인하고 한국어 문구를 서버에서 선택한다. 분당 20건, 방문별 메시지 제한 적용.
- `POST /:store/interpreter-reply`: 해당 샵의 사장님만. 원 요청의 방문·언어를 조회하여 한국어 답변과 손님 번역을 서버에서 선택한다. 다른 방문/다른 샵으로 답변 불가.
- 원 요청 ID와 결정적인 답변 ID로 중복 요청을 하나의 기록으로 처리한다. 일반 메시지 경로는 통역 메타데이터 및 예약된 ID 접두어를 받지 않는다.
- 주문/예약을 실제 제출할 때 당시 언어와 확정된 기록을 receipt 메시지에 남긴다. 재전송이나 화면 언어 변경으로 최초 언어가 바뀌지 않는다. 주문 항목은 한국어와 원문을 함께 표시한다.
- 새 요청/답변은 라미 알림에 표시한다. 작성 중인 입력과 스크롤을 보존한다.
- 기본 데모 로그인은 실제 계정 인증이 아니다. 기존 샵별 토큰 접근 제어를 유지한다.

## 검증

- `npm test`: 40개 통과. 9개 언어/6개 상황/별칭, 수량·부정문 거절, 중복 방지, 방문 분리, UI 언어 변경 후 답변 언어 고정, 기존 주문/예약/게임 회귀 검증.
- `node scripts/verify-interpreter.mjs`: 별도 기존 테스트 샵에서 8개 외국어 왕복 통역, Realtime 알림, 중복 방지, 다른 손님·다른 샵 차단, 임의 번역 거부, 주문/예약 언어 보존 통과. 테스트 자격증명은 ignored artifacts에만 저장.
- 브라우저: 로컬 샘플 및 기존 실시간 데모 샵에서 새로고침 없이 베트남어 요청 → 한국어/원문 → 한국어 답변 미리보기 → 베트남어 수신. 390px 모바일 9개 언어 화면에 가로 넘침 없음.

## 배포

Supabase `modu-api` version 8 (health version 6) 적용. GitHub Pages와 기존 소유자 전용 Sites는 동일 소스/정적 결과물을 배포한다. 공개 권한을 새로 확장하지 않는다.
