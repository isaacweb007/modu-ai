# v5.18 · 주문·예약 변경과 취소 확인

프로덕션북 통합 시연 `#integrated-demo`에서 손님이 확정한 매장 주문, 예약, 온라인 배달에 변경·취소를 요청할 수 있습니다. 메뉴판 등록과 사장님 승인, QR, 언어 선택, 손님 요청부터 이어지는 기존 시연을 유지합니다. 기존 5.17의 확정 후 재시작 방식은 직원 확인이 필요한 변경 요청으로 바꿨습니다. 확정 전에는 입력을 자유롭게 수정할 수 있습니다.

## 처리 규칙

| 상황 | 확인 권한 | 승인 결과 |
| --- | --- | --- |
| 조리 전 주문 변경·취소 | 홀 또는 사장님 | 변경 내용 적용 또는 취소 완료 |
| 조리 시작 후 주문 변경·취소 | 사장님 | 메뉴 변경은 변경된 내용으로 준비 재시작, 취소는 작업 종료 |
| 예약 변경·취소 | 홀 또는 사장님 | 일정·인원 변경 또는 예약 취소 |

손님 화면의 ‘변경 요청’은 기존 입력 폼을 엽니다. 작성 중인 내용은 기존 주문에 반영하지 않습니다. 같은 내용이나 잘못된 입력은 제출할 수 없습니다. 작성 그만두기로 기존 내용에 돌아갈 수 있습니다. 요청 제출 후에는 현재 내용과 변경 요청 내용을 나란히 검토할 수 있습니다. 배달 주소는 번역 과정에서 변경하지 않습니다.

‘취소 요청’을 누른 것만으로 주문이나 예약을 취소하지 않습니다. 검토 중에는 기존 기록을 유지하며 자동 재생과 다음 조리 단계를 멈춥니다. 홀과 사장님 중 허용된 역할만 승인·거절 버튼이 나타납니다. 주방은 승인할 수 없습니다. 조리 중이거나 준비 완료 상태인 주문은 사장님만 변경·취소를 승인할 수 있습니다.

승인은 같은 주문·예약 식별자에 반영합니다. 변경 시 메뉴·수량·총액·예약 일정·인원·주소·연락처가 일관되게 바뀝니다. 조리 시작 후 메뉴·수량이 바뀌면 ‘접수됨’으로 돌아가 주방이 변경 메뉴로 다시 준비하도록 합니다. 배달 주소·연락처만 바뀐 경우에는 조리 상태를 유지합니다. 취소 승인 후에는 ‘취소 완료’를 표시하고 조리·완료 버튼과 준비 완료 알림을 제거합니다. 거절하면 기존 내용과 상태를 유지합니다.

손님은 선택한 언어로 처리 결과를 받습니다. 홀·사장님에게는 한국어와 변경 내용의 원문이 보입니다. 주방에는 메뉴·수량·상태만 전달하며 배달 주소·연락처·가격은 변경 요청에도 노출하지 않습니다. 예약은 주방 작업을 생성하지 않습니다. 처리 기록에는 변경·취소 종류, 승인·거절 여부, 처리 역할을 남깁니다. 기록이 생기면 ‘이전’ 버튼은 비활성화하고 ‘처음부터’로 새 시연을 시작할 수 있습니다.

중복 제출과 승인, 이전 요청·실행·수정 버전에서 온 버튼 동작을 차단합니다. 변경 작성·검토 중에는 자동 진행을 멈추며 승인·거절은 직접 선택합니다. 모바일은 현재 처리 역할 화면을 따라가고 역할 버튼으로 다른 화면을 볼 수 있습니다.

통합 시연 상태와 처리 기록은 페이지 메모리에만 존재하며 새로고침하면 초기화됩니다. 실제 주문·예약, AI, 결제·환불, 이메일, 백엔드 권한·데이터에는 변경이 없습니다. 별도 손님·직원 앱과 연동되는 실제 거래 기능으로 배포한 것은 아닙니다.

검증: 125개 테스트 통과. 모든 주문 단계의 권한, 승인 전 내용 유지, 변경·취소 승인과 거절, 조리 시작 후 사장님 전용 처리, 예약의 주방 분리, 배달 정보 제한, 잘못된 입력, 중복·이전 동작 차단과 9개 언어 렌더링을 검증했습니다. 책 모듈 번들 검사도 통과했습니다.
