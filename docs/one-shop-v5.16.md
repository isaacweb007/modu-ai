# v5.16 · 세 가지 통합 시연

프로덕션북 `#integrated-demo`에 매장 주문·예약·온라인 배달 선택을 추가했습니다. 세 시나리오 모두 메뉴 사진 선택 → 첨부 → 메뉴 정리 → 사장님 검토·승인 → QR → 라미 인사·언어 선택부터 시작합니다. 기본 손님 언어는 베트남어입니다.

- 매장 주문: 7번 테이블에서 김치전 1개 요청 → 원문·한국어 통역 → 사장님 답변 → 손님 확인 → 홀 접수 → 주방 준비 → 준비 완료 알림. 15장면입니다.
- 예약: 온라인 손님이 다음 날 19:00, 2명 예약 요청 → 통역·답변 → 손님 예약 신청 → 홀 예약 확정 → 사장님이 확정 알림 → 손님 알림. 14장면입니다. 예약 날짜는 시연 시작 시 샵 시간대 기준으로 정해집니다. 주방에는 조리 주문을 만들지 않습니다.
- 온라인 배달: 김치전 1개 배달 요청 → 통역·답변 → 손님이 메뉴·금액·샘플 주소·연락처 확인 → 홀 접수 → 주방 준비 → 준비 완료 알림. 15장면입니다. 배달 출발·도착을 실제로 처리하거나 주장하지 않습니다.

배달 주소 `DEMO · 12 Đường Mẫu, Quận 1, TP. Hồ Chí Minh`와 연락처 `+84 000 000 000`은 가상 정보로 표시합니다. 손님 확인 화면과 손님·홀·사장님 주문 기록에 동일한 정보를 유지합니다. 주방에는 조리에 필요한 정보만 표시합니다.

시나리오 변경은 재생을 중단하고 메뉴판 등록부터 새 실행으로 시작합니다. 이전 승인·주문·예약과 대기 타이머를 재사용하지 않습니다. ‘처음부터’와 완료 후 다시 재생은 현재 선택한 시나리오를 유지합니다. 뒤로 가기는 이후 알림·상태를 되돌립니다. `?scenario=dineIn|booking|delivery#integrated-demo`로 선택한 시나리오를 공유할 수 있습니다.

QR 이미지와 표시 링크는 일치합니다. 매장 QR에는 `table=7`, 온라인 QR에는 테이블 번호가 없습니다. 9개 언어 × 매장·온라인 진입의 18개 QR 자산을 로컬 QR 인코더로 생성했습니다. 외부 QR은 같은 8개 메뉴를 가진 격리된 손님 샘플 앱을 열며, 통합 시연 안의 QR 버튼은 현재 시나리오를 이어갑니다.

선택 버튼은 현재 상태·키보드 포커스를 표시합니다. 한국어 기본과 9개 언어를 지원하고, 모바일에서는 현재 역할 화면을 따라갑니다. 책 언어 변경에도 선택한 시나리오와 단계가 유지됩니다. 진행률과 마지막 장면은 예약 14단계, 주문 15단계에 맞게 바뀝니다.

기존 개별 메뉴 등록·로그인 복구·주문 시연을 유지합니다. 실제 AI, 결제, 업로드, 메일, 인증, Supabase 작업은 추가하지 않았습니다. 통합 시연의 상태는 페이지 메모리에만 있고 기존 샵 데이터를 변경하지 않습니다.

검증: 테스트 110개 통과. 세 시나리오를 실제 브라우저에서 메뉴 등록부터 마지막 알림까지 수동으로 검증했습니다. 배달 주소·연락처, 예약의 주방 제외와 사장님 알림, 390px 모바일 선택 버튼과 9개 언어 전환의 가로 넘침·누락 문구·상태 보존을 점검했습니다.

모바일 예약 자동 재생은 사진 등록부터 14번째 손님 확정 알림까지 정상 종료했고, 배달의 홀 접수 화면에서 주소·연락처와 접수 버튼을 화면 안에서 확인했습니다. 브라우저 오류는 없었습니다.
