# 원샵 5.13 — 프로덕션북 사장님 로그인·복구 시연

사용자 요청: 프로덕션북 안에서 사장님 로그인부터 비밀번호 복구, 기존 샵과 주문 확인까지 한 번에 시연. 실제 메일은 보내지 않는 데모만 구현.

## 사용자 흐름

목차의 **사장님 로그인·복구 시연** 또는 `#owner-demo` 링크를 열고 **전체 시연 시작**을 누른다.

1. 주모 사장님 로그인 화면에서 비밀번호를 잊은 상황을 소개한다.
2. 등록 이메일을 확인하는 장면을 보여준다. 가상 주소 `owner@example.com`을 사용한다.
3. 화면 안의 가상 메일함에서 재설정 안내를 확인한다.
4. 새 비밀번호를 정하는 장면을 보여준다. 입력 필드 대신 가상 표시만 사용한다.
5. 새 비밀번호로 다시 로그인하는 장면을 보여준다.
6. 기존 주모 샵 정보를 확인한다.
7. 주문함을 열어 같은 주문 번호·테이블·배달 정보·상태를 확인한다.

재생은 명시적으로 누른 뒤에만 시작한다. 일시정지, 이전/다음, 단계 바로 선택, 처음부터 재생을 제공한다. 수동 조작과 다른 시연 재생, 페이지 숨김, 시연 영역을 벗어남, 모션 감소 설정 변경 시 자동 재생을 멈춘다. CSS 모션은 기기의 모션 감소 설정을 따른다. 재생 중 초점은 자동으로 이동시키지 않는다.

마지막 화면은 샵·주문·예약·메뉴 탭을 제공한다. 주문은 샘플 4건, 메뉴 8개, 예약 3건이다. 옆의 복구 전후 비교표는 같은 스냅샷의 개수를 표시한다. 모바일에서는 앱 화면 아래에 비교표를 둔다. 언어 또는 화면 크기가 바뀌어도 진행 단계와 선택한 기록 탭, 동일한 샘플 스냅샷을 유지한다.

## 실제 서비스와 분리

- `owner-journey-state.js`는 기존 주모 샘플 생성기를 사용해 페이지 메모리에만 가상 기록을 만든다.
- 실제 사장님 인증·저장소·관리 세션·Supabase API를 읽거나 변경하지 않는다.
- 이메일 발송, 비밀번호 수집·저장·변경, 실제 로그인, AI 호출, 결제가 없다.
- 이 시연으로 실제 사장님 권한을 얻을 수 없다. 사장님앱 링크를 열면 기존 로그인 절차를 그대로 거친다.
- 독립형 이메일 복구 데모 링크와 실제 사장님앱 링크는 별도로 유지한다.
- 백엔드 코드, 스키마, 비밀번호, 기존 주문·예약 데이터는 수정하지 않았다.

## 검증

- 전체 자동 테스트 93개 통과. 기존 88개와 새 여정 검증 5개.
- 새 검증: 전 단계·재생 후 스냅샷 불변, 잘못된 단계·탭 차단, 정지·종료 후 타이머 무효화, 9개 언어, 서버·인증·메일 의존성 없음.
- 프런트엔드 ESM 번들 검사 통과.
- 실제 브라우저에서 전체 자동 재생이 주문함까지 완료되는 것과 예약 탭을 확인했다.
- 모바일 390px 뷰포트에서 9개 언어 모두 주문 4건, 단계·탭 유지, 가로 넘침과 누락 문구가 없음을 확인했다.
- 밝은 프로덕션북 프레임, 파란 라미, 어두운 사장님앱 화면을 기존 디자인에 맞췄다.
