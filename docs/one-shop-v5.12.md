# 5.12.0 — 이메일 비밀번호 복구 시연

사용자가 이번 단계는 데모 제작이며 실제 이메일 서비스와 계정 복구는 실 개발 때 연결하도록 명확히 지정했다. 따라서 서버 인증·데이터베이스를 변경하지 않고 독립된 복구 시연 화면을 추가했다.

## 체험

사장님 로그인 화면의 `비밀번호를 잊으셨나요?`, `로그인 · 보안`의 `복구 데모 체험`, 프로덕션북 샵 개설 섹션에서 시작한다. 데모 주소는 `jumo/recovery.html?lang=ko&v=5.12.0`이다.

1. 예시 이메일을 입력한다. 기본값은 `owner@example.com`이다.
2. 화면 안의 데모 메일함에서 재설정 안내를 확인한다. 실제 메일 앱이나 서버는 호출하지 않는다.
3. 12–128자의 시연용 비밀번호를 두 번 입력한다. 일치 여부를 확인하며 값은 저장하지 않는다.
4. 완료 화면에서 메뉴 8개·주문 4건·예약 3건을 확인하고 샘플 샵으로 돌아간다. 주문·예약·메뉴·샵 정보 탭에서 재설정 전과 동일한 기록을 볼 수 있다.

## 격리

- `one-shop-email-recovery-sample-v1`에 가상 샵 자료만 보관한다. 기존 사장님 인증·샵 캐시 키에는 접근하지 않는다.
- 이메일은 해당 페이지의 메모리에서만 데모 메일 수신자로 표시하며, 완료·다시 시작 시 제거한다. 비밀번호는 비교 후 폐기한다.
- 링크 사용과 15분 만료는 화면 시연 규칙이다. 인증 토큰이 아니며 실제 사장님 권한을 부여하지 않는다.
- 실제 샵 정보를 불러오거나 비밀번호를 바꾸지 않는다. 서버 API·AI·메일·결제를 호출하지 않는다.
- 실제 비밀번호 재설정에는 검증된 복구 이메일, 발송 서비스, 일회용 서버 토큰, 요청 제한, 기존 세션 폐기가 필요하다. 현재 샵의 공개 연락 이메일을 본인 확인 없이 복구 주소로 사용해서는 안 된다.

## 화면과 검증

기존 어두운 채팅 UI와 라미를 유지했다. 데스크톱에는 단계별 안내, 모바일에는 가로 4단계 표시를 배치했다. 키보드로 폼과 기록 탭을 이동할 수 있다. 기존 9개 언어의 문구를 추가했으며 실제 출시 전 현지 언어 검수가 필요하다.

자동 테스트 88개 통과. 새 테스트는 샵·메뉴·주문·예약의 동일성, 기존 인증 저장값 보존, 비밀번호·이메일 비저장, 단계 건너뛰기·만료·중복 사용·불일치 거부, 9개 언어 완전성 및 서버 호출 부재를 검증한다. ESM 번들 검사와 데스크톱·390px 모바일에서 전체 시연 흐름을 확인했다.

배포는 기존 GitHub Pages 공개 주소와 기존 소유자 전용 Sites에 동일 소스로 진행한다. Supabase 인증·스키마·함수의 변경은 없다.
