# 원샵 5.8 · 예약·배달 시연, QR 인트로와 직원 역할

## 두 화면 시연

프로덕션북 `#live-demo`에서 매장 주문·예약·온라인 배달을 선택한다. 손님 언어는 베트남어로 시작하며 9개 언어를 지원한다. 사장님 화면에는 한국어 뜻과 손님 원문이 함께 나온다. 예약과 배달에도 준비된 사장님 답변을 손님 언어로 표시한다.

- 매장: 라미와 언어 선택 → 7번 테이블 주문 요청 → 통역 → 사장님 답변 → 손님 확인 → 접수 → 준비 → 완료 알림.
- 예약: 라미와 언어 선택 → 내일 19시 2명 요청 → 통역 → 방문 정보 확인 → 예약 신청 → 사장님 확정 → 손님 언어로 확정 알림. 시연 시작 시각을 기준으로 호찌민 시간대의 내일 날짜를 고정한다.
- 배달: 라미와 언어 선택 → 김치전 1개 요청 → 통역 → 주소·연락처 확인 → 주문 확정 → 접수 → 준비 → 준비 완료 알림. 주소와 전화는 명시적으로 가상 정보이며 두 화면에 함께 표시한다. 실제 배달 출발이나 결제 완료로 표시하지 않는다.

전체 재생·일시정지·다음 단계·처음부터와 단계별 역할 버튼을 제공한다. 시나리오 또는 언어를 바꾸면 새 시연으로 시작한다. 새로고침하면 정지 상태로 복구한다. 타이머 취소 후 늦게 도착한 콜백은 새 시연을 변경하지 않는다.

이 시연은 하나의 독립 상태를 표시하는 두 앱 화면이며 실제 주문 API를 호출하지 않는다. `one-shop-book-showcase-v2`에 진행 메타데이터만 저장한다. 기존 샵의 주문·예약과 별개이며 AI·결제 연결을 추가하지 않았다.

## QR 첫 화면

실제 손님앱에도 라미 인사 → 9개 언어 선택 → 시작 버튼 순서를 적용했다. 기본 한국어, 명시된 URL 언어는 해당 언어로 시작한다. QR의 샵·테이블 파라미터를 유지한다. 언어를 선택하고 시작하기 전에는 손님 세션을 만들지 않는다. 프로덕션북 시연의 첫 장면도 같은 인트로 컴포넌트를 사용한다.

## 직원 기능을 넣는 이유와 권한 구조

사장님 계정을 공유하면 주문을 누가 처리했는지 알기 어렵고 매출·연락처까지 과도하게 노출된다. 별도 복잡한 관리 앱보다는 같은 디자인의 업무별 모바일 화면이 적합하다. 1인 샵은 사장님 화면만 사용하고 직원이 생길 때 추가할 수 있다.

- 사장님: 슈퍼관리자. 직원 등록·삭제·권한 변경, 세금·정산은 사장님 전용.
- 홀: 테이블 주문·예약·손님 요청 확인, 주문 접수와 서빙 완료.
- 주방: 메뉴·수량 확인, 접수된 주문의 준비 시작·완료, 메뉴 판매 가능 여부 변경.
- 배달 주소·연락처와 매출은 별도 허용 항목이다. 주방 기본 권한에는 포함하지 않는다.
- 보기 권한과 실행 권한을 분리한다. 보기 권한을 없애면 해당 실행 권한도 해제한다. 제한된 설정 변경은 샵 연락처까지만 허용한다.

사장님앱 `#team`에서 등록·권한 수정·직원 화면 링크·삭제·최근 처리 기록을 체험한다. 기본 샘플 직원은 홀 Minh, 주방 Jin이다. 각 동작은 최신 권한을 다시 검사하고, 주문 상태는 접수 대기 → 접수 → 준비 → 준비 완료 → 서빙 완료 순서만 허용한다. 삭제된 직원은 열려 있던 화면도 잠긴다. 초기화 후에도 이전 직원 링크가 다시 유효해지지 않도록 새 ID를 만든다.

### 데모 경계와 운영 구현 계획

이번 직원 등록/권한/삭제와 업무 처리는 **같은 브라우저의 로컬 샘플**에서만 동작한다. 링크에 있는 직원 ID는 인증 자격 증명이 아니다. 홀·주방 역할별 체험 링크는 다른 휴대폰에서도 열리지만 각 기기의 **독립 샘플**이다. 실제 계정이나 기기 간 직원 권한 동기화를 구현했다고 간주하면 안 된다. 직원 데모는 기존 클라우드 샵 API에 접근하지 않는다.

운영 버전은 만료되는 일회용 초대 → 직원 본인 인증 → 샵별 멤버십과 역할 연결로 구성한다. 서버에서 요청마다 샵 소속과 권한을 확인하고, 삭제 시 모든 기기의 세션을 해제한다. 주소·전화·매출은 권한에 맞는 필드만 응답하고, 주문 처리와 설정 변경은 담당자·시각과 함께 감사 기록을 남긴다. 이 로직과 데모 한계를 프로덕션북 직원 섹션 및 앱 안에 9개 언어로 설명한다.
