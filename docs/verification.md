검증일: 2026-10-27. 대화 중심 개편. 기존 5종 디자인 UI를 제거하고 손님·사장님이 같은 최소 채팅 구조를 사용한다.

## 자동 검사

`npm test`로 13개 그룹을 확인한다.

- 9개 언어 키 일치, 18개 장, 메뉴·이미지 경로.
- 주문 합계, 스냅샷 가격, 중복 주문 방지, 상태 전이.
- 주문 직전 가격 변경·품절 재확인.
- 가게 외 질문, 방문·일 질문 예산, 동적 가게 주소·메뉴.
- 가위바위보 9개 결과, 룰렛 4개 결과, 한 번 참가와 보너스 제한.
- 메뉴 승인 없는 개설 방지, 단계와 가게 정보 유지.
- 결제 중복 포인트 방지, 다른 방문의 결제 거부, 잔액 부족 쿠폰 거부.
- 지난 날짜·과대 인원 예약 거부, 중복 예약 방지, 방문 소유권과 취소 종료 상태.
- 재고 갱신·직원 업무 완료·결제 완료 주문만 CSV 내보내기.
- 대화 기록 유지와 상한, 배포 JavaScript 문법.

## 브라우저에서 확인한 흐름

- 매니저 데모 시작 → 상호 → 메뉴 이미지 첨부 → 매장 이미지 첨부 → 주소·이메일·사이트 → 메뉴 승인 → QR 생성.
- 첨부 이미지는 새로고침 후 IndexedDB에서 다시 표시됨. 영상 형식·용량 제한은 구현했으며 실제 영상 재생 QA는 별도.
- 손님 메뉴 → 김치전 129,000₫ 주문 → 데모 결제 → 129P 적립 → 100P 쿠폰 → 29P 잔액.
- 다음 날짜 19시 2명 예약 → 오너의 예약 확인 → 손님 예약에 확인 완료 반영.
- 가게 외 코드 요청은 제한 안내. 음식이 차갑다는 불만은 오너 확인 목록에 나타남.
- 자재 쌀 12kg 저장, 직원 테이블 준비 업무 저장, 세무 자료에 결제 완료 금액 표시.
- 375px 모바일 9개 언어 첫 화면에 가로 넘침 없음. 모바일 메뉴와 새 대화 동작 확인. 812×375 가로 화면에서도 가로 넘침 없이 입력창 사용 가능.

## 남은 실제 서비스 범위

이 버전은 같은 브라우저에만 데이터를 보관하는 공개 시나리오 데모다. GPT·OCR·실제 인증·주문·예약·결제·직원 알림·세금 신고·POS 동기화는 호출하지 않는다. 다른 기기 QR 방문에는 수정된 가게 정보나 기록이 전달되지 않는다. 서버 구현 단계에서 테넌트별 DB, 로그인·역할 권한, 업로드 보관 정책, 서명 검증, 결제 웹훅, 서버 예산, 주문 동시성 및 실제 POS 연동을 검증해야 한다.

가위바위보 결과·재참가 금지, 룰렛 결과·재참가 금지, 결제 내역 CSV 다운로드도 브라우저에서 확인했다. 프로덕션북의 내장 앱이 새 대화 UI로 표시된다.

과거 v2 검증은 Git 이력에 보관한다. 사진·원본 에셋은 작업 폴더에 유지한다.
