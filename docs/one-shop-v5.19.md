# v5.19 · 거절 사유 통역과 처리 기록

프로덕션북 `#integrated-demo`에서 매장 주문·예약·온라인 배달의 변경·취소 요청을 거절할 때 사유를 선택합니다. 실제 AI·결제·메일·외부 알림은 호출하지 않습니다.

- 요청 메뉴 품절: 주문 메뉴 변경 요청
- 날짜·시간 만석 / 요청 인원 좌석 부족: 예약 변경 요청
- 조리 시작으로 처리 어려움: 조리 시작 후 주문 변경·취소
- 직원과 직접 확인 필요: 모든 요청

홀과 사장님은 사유 선택 전 거절할 수 없습니다. 조리 시작 후 주문 검토는 기존처럼 사장님만 가능합니다. 선택하면 손님 언어의 안내문을 미리 보고, 거절 버튼을 눌러 전달합니다. 기존 주문·예약과 준비 상태를 유지하고 손님은 다시 요청할 수 있습니다. 사유 초안은 검토자별로 분리됩니다. 승인에는 거절 사유가 필요하지 않습니다.

한국어·영어·베트남어·중국어·일본어·크메르어·인도네시아어·라오어·힌디어의 준비된 문구를 사용합니다. 사장님 처리 상세 기록에는 접수한 요청의 한국어·원문, 선택 사유, 실제 손님에게 표시한 안내문의 한국어·원문, 처리자 이름·역할과 처리 시각을 저장합니다. 시연용 직원은 김하늘(홀), 이주모(사장님)입니다. 처리 시각은 클릭 당시 ISO 시각을 저장해 샘플 샵 시간대 UTC+7로 표시합니다. 재렌더링·언어 전환·재요청이 이전 기록의 내용이나 시각을 바꾸지 않습니다. 승인도 처리자·시각을 기록합니다.

기록은 현재 통합 시연의 메모리 안에만 유지됩니다. 새로고침·처음부터·시나리오 변경 시 초기화됩니다. 실제 샵 데이터나 직원 계정에는 기록하지 않습니다. 주방에는 배달 주소·전화번호·요청 원문·처리자 상세 기록을 전달하지 않습니다. 서버 보안/실제 직원 인증을 대신하는 기능이 아닙니다.

## 검증

- Node 자동 검증 132개 통과: 9개 언어, 상황별 사유, 필수 입력, 역할 제한, 오래된 요청과 중복 처리 차단, 변경 거절 시 원래 값 유지, 이력 불변성, 배달 개인정보·HTML 이스케이프.
- 브라우저: 베트남어 매장 취소를 홀이 거절, 조리 중 배달 취소를 사장님이 거절, 모바일에서 예약 6명 변경을 홀이 좌석 부족 사유로 거절.
- 390px 모바일에서 역할 전환과 상세 기록 확인, 가로 넘침 없음. 기록과 통역은 페이지 내 동기화.
- 모듈 번들 검사 통과. 공개 게시 후 배포된 버전과 거절 시연을 다시 확인합니다.
