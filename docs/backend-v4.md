# 공유 가게 백엔드 4.0

전용 Supabase: `modu-ai` / `zaorqadwuqvfpwjefomh` / Singapore. 다른 프로젝트와 DB를 공유하지 않는다.

## 데이터와 권한

가게 공개 정보·메뉴는 `modu_stores`, 소유자의 대화와 운영 메모는 `modu_owners`, 방문은 `modu_visits`, 주문·예약·대화·업로드는 각각 분리된 테이블에 저장한다. 소유자와 손님 키는 서버에서 256비트 난수로 발급하고 SHA-256 해시만 저장한다. 원본 키는 요청의 `x-modu-token` 헤더로 전달하며 URL·QR·로그에 넣지 않는다.

모든 앱 테이블에 RLS와 직접 클라이언트 접근 거부 정책을 적용했다. anon/authenticated 테이블 권한과 RPC 실행 권한도 회수했다. 브라우저는 테이블에 직접 접근하지 않는다. Edge API가 매 요청의 가게 ID와 관리/방문 키를 검사한다. `verify_jwt=false`는 이 사용자 지정 인증을 사용하기 위한 설정이며, 관리 작업과 방문 기록에는 키 검사를 생략하지 않는다. 서비스 역할 키는 Edge 런타임 환경에만 있다.

스토리지 `modu-store-media`는 비공개다. 소유자만 업로드하고, 공개된 가게 또는 권한이 있는 관리 화면에 1시간 서명 URL을 발급한다. 이미지 5MB, 영상 25MB, 가게별 30개 한도이며 MIME·파일 시그니처를 검사한다. SVG/HTML을 받지 않는다. 서명 URL을 가진 사람은 만료 전 해당 공개 가게 자료를 볼 수 있다.

## API

기본 경로: `/functions/v1/modu-api`.

| 경로 | 용도 | 권한 |
| --- | --- | --- |
| POST `/create` | 가게 생성, 관리 키 발급 | 공개, IP 제한 |
| GET `/:store/public` | 게시된 가게·메뉴·사진 | 공개 |
| POST `/:store/visits` | 테이블 방문 키 발급 | 게시된 가게, IP 제한 |
| GET `/:store/snapshot` | 가게·주문·예약·대화 | 소유자 전체, 손님 본인 |
| PUT `/:store/store` | 가게·메뉴·게시 상태 저장 | 소유자, 공개/운영 버전 충돌 검사 |
| PUT `/:store/workspace` | 매니저 대화·재고·직원 메모 | 소유자, 버전 충돌 검사 |
| POST `/:store/orders` | 서버 가격으로 주문 | 해당 가게 손님 |
| PATCH `/:store/orders/:id` | 주문 상태 다음 단계 | 해당 가게 소유자 |
| POST `/:store/reservations` | 예약 요청 | 해당 가게 손님 |
| PATCH `/:store/reservations/:id` | 예약 확인·취소 | 소유자, 손님은 자기 예약 취소만 |
| POST `/:store/messages` | 시나리오 대화·요청 기록 | 해당 방문 손님 |
| PATCH `/:store/review/:id` | 불편/직원 요청 확인 | 해당 가게 소유자 |
| POST `/:store/media` | 사진·영상 업로드 | 해당 가게 소유자 |

주문 RPC는 방문 행과 메뉴를 잠그고 서버 메뉴에서 가격·판매 여부·수량을 검증한다. 손님이 보낸 금액을 사용하지 않는다. 메뉴 버전 변경은 재확인을 요구한다. 방문+요청 ID의 고유 제약과 잠금으로 네트워크 재시도와 동시에 누른 주문의 중복을 방지한다. 프런트엔드는 완료 전 요청 ID를 유지한다. 예약도 방문+요청 ID로 중복 방지하며 날짜·시간·인원·가게 시간대를 검사한다.

## 실시간

DB 변경 트리거가 `modu:<store UUID>` 공개 Broadcast 채널에 빈 갱신 신호를 보낸다. Supabase가 붙이는 메시지 전달용 ID 외에 주문·고객·금액·대화 데이터는 없다. 클라이언트는 신호를 받으면 자기 키로 API를 다시 조회한다. 신호가 위조되어도 비공개 내용을 읽거나 수정할 수 없다. 20초 보조 동기화, 탭 복귀 및 네트워크 재연결 동기화가 있다. 입력 중인 폼은 실시간 렌더링으로 지우지 않는다.

## 현재 범위

현재 화면은 최근 주문 500개·예약 500개·방문 500개·메시지 2,000개를 불러온다. DB에는 기록이 계속 저장된다. 대규모 운영에는 페이지 단위 조회, 계정 로그인·관리 키 회수, 백업/보존 정책, 감사 로그, 봇 방지와 요금제별 한도를 추가해야 한다. 현재 재고·직원 업무는 수동 메모이며 세금 계산·신고가 아니다. 실제 결제 상태는 DB 제약으로 `unpaid`만 허용한다. AI API 호출은 없다.

오래된 소유자 화면의 저장 충돌은 덮어쓰지 않고 거절한다. 현재 서버 상태를 다시 불러오며 입력 초안은 기기의 `modu-conflict-draft:<store>` 키에 보존한다. 실시간 연결이 끊기면 상태를 표시한다. 네트워크 실패를 주문·예약 성공으로 표시하지 않는다.
