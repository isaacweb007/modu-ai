# 원샵 프로덕션북 편집·UI 점검

## 발견한 문제

- 서비스 체험 전에 라미 소개 5개 장이 삽입되어 제품의 가치를 확인하기까지 길다.
- 통합·주문·개설·로그인 시연이 모두 펼쳐져 같은 설명과 조작을 반복한다.
- 로그인 안내를 덧붙이는 applyOwnerBook이 로드맵·다음 결정·FAQ까지 동일한 문장을 주입한다. 각 장의 목적이 흐려졌다.
- 표지에 동등하게 보이는 링크가 5개 이상 있어 첫 행동이 불명확하다.
- 사업 모델에 실제로 없는 요금·매출 계산을 언급한다. 출시 계획은 단계별 완료 조건보다 로그인 설명을 반복한다.
- 현재 작동하는 별도 샵 앱, 브라우저 안의 시연, 아직 연결하지 않은 기능을 한눈에 비교하는 곳이 없다.
- 목차는 거의 모든 항목이 펼쳐져 있고 시연 바로가기는 검색 대상에서 빠져 있다.
- 모바일 본문 일부는 13px, 보조 문구는 7–10px로 작다. 고정 하단 이동 바가 시연을 가린다.

## 적용 방향

UI/UX Pro Max의 제목 계층·고정 내비게이션·글자 크기 지침과 frontend-design의 사용자 중심 카피라이팅 지침을 적용한다. 외부 실적·고객·효과 수치를 만들지 않는다.

읽는 순서: 원샵 이해 → 직접 체험 → 함께 운영 → 사업·출시 검증 → 라미와 브랜드 → 현재 범위와 FAQ.

표지는 원샵의 한 문장 가치와 대표 시연 하나를 중심으로 한다. 기존 라미 블루 #AEC8EB, 잉크 #172D46, 햇살 #FFE395, 구름 #F5FAFF, 흰색 #FFFFFF를 유지한다. Pretendard를 제목·본문에 함께 쓰고, 제목은 명확한 줄바꿈과 700–800 굵기, 본문은 400–500 굵기와 1.8 행간을 적용한다. 한국어와 각 언어의 문장 길이를 따로 고려한다.

표지: [주요 메시지 + 시연 버튼] [동네 샵과 라미 이미지]
본문: [장의 목적·핵심 문장] → [설명/실제 체험] → [다음 관련 장]
시연: 통합 시연은 펼치고, 세부 시연은 필요할 때 연다. 기존 모든 앵커는 유지한다.

장마다 하나의 질문에 답하도록 카피를 정리한다. 로드맵은 출시 준비 조건, 사업은 구독 가설과 비용, FAQ는 현재 기능 범위를 맡는다. 사진·메뉴 금액·혜택의 가상 성격은 실제로 판단이 필요한 위치에만 안내한다.

## 반영 결과와 확인

- 23개 장과 기존 URL 앵커를 보존하고 6개 묶음으로 재배치했다. 라미의 24개 표정, 직업, 굿즈, BI와 다운로드도 유지했다.
- 통합 시연을 표지의 주요 행동으로 설정했다. 주문 통역·메뉴 등록·로그인 복구는 접어 두고 필요할 때 열며, 직접 링크로 들어오면 자동으로 펼친다.
- 로그인 설명의 일괄 주입을 제거했다. 각 장의 원문을 직접 관리하고 9개 언어에 편집 방향을 동일하게 적용했다.
- 역할과 권한, 주문 진행, 개인정보, 비용 통제를 별개 질문으로 분리했다. 사업·출시 장에 구독 검증, 실제 비용, 단계별 완료 조건과 아직 정해야 할 결정을 담았다.
- 기능 범위 표를 신설했다. 책 속 임시 시연 / 서버에 기록하는 별도 앱 / 아직 연결하지 않은 기능을 구분한다.
- 모바일 본문은 16px로 조정했다. 목차 검색에 세부 시연을 포함하고, 시연을 볼 때 하단 장 이동 바를 숨긴다. 표는 모바일에서 세로로 읽는다.
- 자동 테스트 157개 통과. 9개 언어에서 23개 장·기능 표가 존재하고 누락 문자열·가로 넘침이 없음을 확인했다. 데스크톱 1440px, 모바일 390px 화면을 검토했다.
- 실제 브라우저에서 목차 검색 → 접힌 복구 시연 열기 → 베트남어 전환, 모바일 검색 → 기능 범위 이동을 확인했다. 통합 시연에서 변경 요청 → 홀 대안 → 손님 재요청 → 홀 승인 후 네 역할의 최종 합의 반영을 확인했다.

## 아직 결정·검증할 것

파일럿 국가·샵·책임자, 구독에 포함할 사용량과 지원 범위, 실제 AI 비용 상한, 결제·POS 대조, 계정 복구 운영, 기록 보관·삭제 기준, 언어별 현지 검수는 출시 준비 항목으로 남겨 두었다. 이 편집 작업에서 실제 AI·결제·메일 연결이나 새 운영 데이터를 만들지 않았다.
