# 원샵 앱 UI·문구 점검 v5.23

## 문제와 적용 방향

- 손님이 메뉴·장바구니·주문 내역을 반복해서 열면 대화에 같은 카드가 계속 쌓인다. QR의 테이블 정보는 진입 뒤 작게 숨겨지고 장바구니는 멀리 떨어져 있다.
- 사장님 대시보드가 요약·매출·통역·주문·예약·손님 대화·미디어를 한꺼번에 펼친다. 처음 필요한 접수 작업이 밀린다.
- 직원 주문 목록은 완료·대기·처리 가능 주문이 섞인다. ‘보기 전용’만으로는 다음 담당자가 누구인지 알기 어렵다.
- 새 메시지 알림이 작은 화면의 작업을 가린다. 모바일 메뉴의 초점과 뒤로 가기, 화면 갱신 시 작성 중인 메시지도 점검한다.

기존 라미와 차분한 대화형 UI를 유지한다. 색은 배경 #181818, 표면 #222222, 경계 #454545, 본문 #F2F2F2, 보조 #B9C2CD, 강조 #AEC8EB. Pretendard 제목 24–30px, 본문·입력 16px, 보조 13–14px. 중요한 주문 위치와 다음 처리 버튼에만 강조색을 쓴다.

손님: [샵·테이블] [메뉴 / 라미 / 주문 / 예약] → [선택한 메뉴] → [수량·이용 정보 확인] → [주문 전송] → [상태·다음 안내]
사장님: [샵 현황] [주문 / 예약 / 손님 요청 / 운영 자료] → [처리할 주문] → [상태 변경]
직원: [역할·샵] [처리할 주문 / 전체 / 완료] → [위치·메뉴·수량] → [내 역할의 다음 작업]

대화 기록은 보존하되 내비게이션은 같은 화면을 다시 열도록 한다. 기존 서버 인증·직원 권한·동기화는 유지한다. 준비된 응답과 결제 데모 범위도 그대로 유지한다.

## 구현과 검증

- 손님: 라미 언어 선택 화면 유지, QR 테이블 사전 입력 후 확인, 메뉴·대화·주문·예약 고정 이동, 메뉴별 수량 조절과 하단 합계. 주문 확인은 별도 단계이며 자동 전송하지 않는다. 최신 진행 주문이 먼저 나온다.
- 사장님: 주문·예약·손님 요청·운영 자료 탭. 완료 주문과 보고 자료를 기본 화면에서 분리하고 경로 필터의 수치를 현재 주문 목록에 맞춘다.
- 직원: 처리할 주문 우선. 기존 권한에 따라 홀 접수·서빙, 주방 조리 시작·준비 완료만 노출한다. 주소·연락처는 기존 deliveryView 권한을 그대로 따른다.
- 문구: 손님에게 사장님용 ‘샵 정보를 바꿔줘’가 나오던 항목을 수정했다. 역할별 다음 행동, 언어별 자연스러운 버튼 이름과 안내 문구를 9개 언어에 추가했다.
- 접근성: 44–50px 주요 터치 영역, 16px 입력 글자, 모바일 메뉴 초점, 뒤로 가기와 작성 중인 질문 유지, 모션 줄이기 지원. 장바구니 버튼을 토스트가 가리지 않도록 조정했다.

검증 날짜: 2026-10-28. `npm test` 164개 통과. 변경한 두 앱 진입점의 구문 검사와 esbuild 번들 검사 통과. 390px 브라우저에서 9개 언어 메뉴의 가로 넘침·깨진 이미지 없음. 한국어 매장 주문, 베트남어 메뉴→테이블 확인→배달 전환→주소·연락처→최종 확인→주문 내역, 브라우저 뒤로 가기와 대화 초안 유지, 직원 주방 준비 완료를 확인했다.

사장님 접수·예약 분리 화면은 배포 대상 밖의 격리된 샘플 fixture에서 확인했다. 기존 실제 사장님 로그인 화면의 보호도 유지된다. 서버 인증·비밀번호·권한·실시간 통신 코드는 변경하지 않았다. 새 순수 로직 테스트는 홀→주방→홀 상태 흐름과 권한 축소, 연락처 비공개, QR 확인 단계, 화면 경로 분리, 9개 언어 누락, 손님 최신 주문 정렬을 검증한다. 실제 AI·결제·메일 발송은 추가하지 않았다.
