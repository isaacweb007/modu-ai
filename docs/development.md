# 모두의 AI 첫 제품 개발 기준

## 확정된 사용자 의도

- 프로젝트 이름은 모두의 AI. 아이작스튜디오와 원컴퍼니 재단의 공동 플랫폼 사업 구상.
- 첫 업종은 레스토랑·식당·카페. 사장님이 AI를 배우지 않아도 만들 수 있어야 함.
- 가게 등록 입력: 상호, 주소, 국가, 전화번호, 이메일, 웹사이트·SNS 주소, 메뉴판 사진 여러 장.
- 손님은 테이블 QR 또는 SNS 링크에서 진입. 언어 선택, 직접 메뉴 선택·주문, 추천 요청, 재료와 매장 질문.
- 사장님에게 구독 서비스 제공, 가게별 AI 링크와 출력 가능한 QR 제공.
- Codex로 개발하고 GPT 계열 모델을 사용. 모델명은 품질·지연·비용 비교 후 선정.

## 먼저 구현할 기능

1. 사장님 계정과 매장 권한. 공개 연락처와 운영 이메일 분리.
2. 매장 등록과 사진 업로드. 개수·용량·형식 검사, EXIF 처리, 원본과 추출 기록 보관 정책.
3. 이미지 이해 모델을 통한 메뉴·가격·통화·옵션 추출. 구조화된 결과와 불확실한 필드 표시.
4. 사장님 승인 후 메뉴 버전 공개. 가격·품절·재료는 원본 데이터로 관리.
5. 공개 매장 경로와 테이블별 QR. 일반 링크와 테이블 주문 세션 구분.
6. 한국어를 포함한 우선 언어의 메뉴·대화. 국가별 통화와 주소 체계.
7. GPT에 승인된 가게 데이터만 제공. `get_menu`, `get_store_info`, `get_ingredient_info` 등 조회 도구.
8. 장바구니 최종 확인 → 서버의 가격·품절·수량·테이블 검증 → 중복 방지 키로 주문 생성.
9. 사장님 주문함에서 접수·조리·완료 상태 전환. 직원 호출과 장애 안내.
10. 파일럿 후 구독·이용량·운영 보고. 음식 결제와 플랫폼 구독 결제는 별도 흐름.

## 데이터 모델 제안

account, organization, store, membership, menu_version, menu_item, menu_option, ingredient, table, guest_session, conversation, message, order, order_item, payment, subscription, audit_event, action_approval.

모든 매장 자원은 store_id로 소유 범위를 검증한다. 주문에는 확정 당시 상품명·가격·옵션 스냅샷을 기록한다. 주문 상태와 결제 상태는 분리한다. API 키는 서버에서만 보관한다.

## 완료 기준

- 다른 매장의 메뉴·대화·주문이 섞이지 않는다.
- 메뉴 사진의 오독을 사장님이 공개 전에 바로잡을 수 있다.
- 품절과 가격 변경이 최종 주문 시점에 검증된다.
- 주문 버튼 연타, 재시도, 결제 알림 반복에 중복 처리가 생기지 않는다.
- 재료 정보가 없거나 알레르기·교차 접촉을 판단할 수 없으면 직원에게 연결한다.
- QR의 재인쇄 없이 최신 메뉴가 표시된다. 외부에서 복사한 QR의 주문 악용을 검증한다.
- 매장에 접수되지 않은 주문을 접수 완료라고 표시하지 않는다.
- 한국어·영어·선정 현지어 평가셋으로 메뉴 추천과 도구 호출 정확도를 측정한다.
- 매장별 토큰·도구·스토리지 비용과 제한을 측정할 수 있다.

## 미확정 의사결정

첫 출시 국가, 첫 매장, 법적 계약 주체와 기관별 역할, 가격과 이용량, POS 연결 대상, 음식 온라인 결제 포함 여부, 운영·고객 지원 주체.

## 다음 구현 순서

실제 매장 한 곳의 정보를 확보 → 로그인과 매장 CRUD → 메뉴 사진 읽기·승인 → GPT 질문 응답 → 공개 매장 링크·QR → 주문함. 이후 현장 검증으로 다음 범위를 정한다.
