# v5.20 · 대안 제안과 손님 수락

프로덕션북 `#integrated-demo`의 매장 주문·예약·온라인 배달 시연에 대안 제안 흐름을 추가했습니다. 변경 요청을 검토하는 홀 또는 사장님이 거절 사유와 함께 다른 메뉴·수량 또는 예약 날짜·시간을 제안합니다.

## 체험 순서

1. 시나리오를 골라 메뉴 등록 → 확인 → QR → 언어 선택 → 요청·통역 → 주문/예약 확정까지 진행합니다.
2. 손님이 변경을 요청합니다.
3. 홀 또는 사장님이 거절 사유를 고르고 ‘다른 메뉴/예약 시간 제안하기’를 누릅니다.
4. 대안을 입력하고 손님 언어 미리보기와 총액을 확인한 뒤 ‘거절하고 대안 보내기’를 누릅니다.
5. 손님은 자기 언어로 현재 내용과 대안을 비교하고 수락하거나 기존 내용을 유지합니다.
6. 수락 결과를 손님·홀·주방·사장님 화면에서 확인합니다. 사장님 처리 기록에는 제안과 응답의 한국어·원문, 제안 직원·시각, 손님 수락·시각이 남습니다.

## 처리 규칙

- 제안을 보낸 것만으로 주문·예약이 바뀌지 않습니다. 수락 대기 중에는 다음 진행과 추가 변경 요청을 잠시 막고 기존 내용을 유지합니다.
- 변경 거절 시 대안 첨부는 선택입니다. 취소 요청에는 대안 작성 기능을 넣지 않았습니다.
- 메뉴 대안은 승인된 8개 메뉴의 전체 주문 구성과 총액입니다. 수량은 각 0~20개, 최소 1개입니다. 배달 주소·연락처는 현재 확정된 값을 유지합니다.
- 예약 대안은 날짜·시간을 수정하고 손님 변경 요청의 인원을 유지합니다. 유효하지 않거나 이미 지난 시간은 차단합니다. 수락 시점에 시간이 지났다면 만료 결과만 기록하고 반영하지 않습니다.
- 기존 내용 또는 거절한 변경 내용과 같은 제안은 보내지 못합니다. 검토자마다 초안을 분리하며 오류가 나도 입력을 유지합니다.
- 조리 시작 후에는 사장님만 제안할 수 있습니다. 이 단계에서 메뉴 대안을 수락하면 주방 준비를 다시 시작하도록 접수 완료 단계로 돌아갑니다.
- 손님이 수락하지 않으면 기존 내역을 유지합니다. 새 변경 요청은 별도 이력으로 남습니다. 제안·응답은 요청/제안 ID, 시연 ID, 리비전과 역할을 검사해 중복·오래된 버튼으로 덮어쓸 수 없게 했습니다.
- 주방에는 메뉴·수량 및 처리 상태만 표시합니다. 주소·전화·가격·직원 상세 이력은 숨깁니다. 예약 대안은 상태만 알리고 예약 날짜·인원은 주방에 표시하지 않습니다.
- 한국어 기본, 9개 언어의 준비된 문구를 사용합니다. 실제 AI·결제·메일·클라우드 변경은 없습니다. 현재 페이지의 시연 기록만 유지하며 새로고침·처음부터·시나리오 변경 시 초기화합니다.

## 검증

자동 검증 142개 통과. 9개 언어 × 세 시나리오, 손님 수락 전 데이터 유지, 수락·거절, 권한·중복 처리, 조리 재시작, 예약 만료, 이력 보존과 주방 개인정보 제한을 검증했습니다. 브라우저에서는 베트남어 메뉴 대안과 네 화면 반영, 390px 모바일 영어 예약 대안과 처리 기록을 확인했습니다. 모듈 번들 검사 및 변경 파일 공백 검사도 통과했습니다.
